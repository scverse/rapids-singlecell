### 0.18.2 {small}`the-future`

```{rubric} Features
```
* Add ``dtype="bfloat16"`` to {func}`~rapids_singlecell.pp.harmony_integrate`: computation stays in float32 while the soft cluster assignments are stored in bfloat16, using about a third less GPU memory. It needs one batch key and falls back to float32 with a warning otherwise {smaller}`S Dicks`
* Add ``shuffle_chunk_size`` to {func}`~rapids_singlecell.pp.harmony_integrate`: cells move between the random update blocks in runs of neighbouring same-batch cells (default 8; ``1`` shuffles every cell independently) {smaller}`S Dicks`

```{rubric} Performance
```
* Speed up {func}`~rapids_singlecell.pp.harmony_integrate` 3.5-5x with one batch key (11.4M cells in 0.65 s, 100M cells in 6 s) and 6x with several keys, using fused clustering and correction kernels without an ``N x K`` similarity matrix. Results stay bitwise reproducible, but seeded results differ from earlier releases. NumPy input is uploaded in chunks, so 100M cells x 50 components fit on a 96 GB GPU {smaller}`S Dicks`
* {func}`~rapids_singlecell.pp.harmony_integrate` draws its update blocks once per call and keeps their counts, so clustering no longer re-reads the assignments or re-sorts the cells every iteration; NumPy input and output are copied through pinned memory by several threads {smaller}`S Dicks`
* {func}`~rapids_singlecell.pp.harmony_integrate` sums cluster counts, centroids and correction right-hand sides exactly in fixed point, and applies the correction and normalization in one pass {smaller}`S Dicks`

```{rubric} Bug fixes
```
* {func}`~rapids_singlecell.pp.harmony_integrate` no longer returns NaN for large ``theta`` or small ``sigma``: diversity penalties are applied in log space and the cluster weights are shifted before they are exponentiated {smaller}`S Dicks`

```{rubric} Misc
```
* ``colsum_algo`` in {func}`~rapids_singlecell.pp.harmony_integrate` no longer has an effect and is kept for compatibility {smaller}`S Dicks`
